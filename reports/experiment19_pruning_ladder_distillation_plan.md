# 实验19：COCO2017 剪枝阶梯与蒸馏恢复

> 这是一份执行方案和结果记录，供人和 AI 共同使用。当前只确定主路线，不宣称 Taylor 已经是最优方法；最终由统一条件下的精度、GMAC 和真实延迟决定。

## 1. 一句话方案

从官方 YOLO11s 开始，只沿 **raw 权重**连续做 Taylor 结构化通道剪枝，保存实际 GMAC 约下降 5%、10%、15%、20% 的四个嵌套节点。全部剪完后，再分别做统一 BN 校准、普通微调和蒸馏恢复。

```text
官方 YOLO11s
  ↓ Taylor + 实际 GMAC 贪心
5% raw → 10% raw → 15% raw → 20% raw
  ↓          ↓           ↓           ↓
分别复制，统一 BN 校准并建立 source
  ↓
四个节点：control 与 YOLO11s KD
  ↓
选择一个均衡节点和一个激进节点
  ↓
两个入选节点：补做 YOLO11m KD 与 DINOv2 KD
  ↓
比较精度、GMAC、真实延迟，选择最终模型
```

## 2. 实验要回答什么

1. YOLO11s 在 COCO2017 上能稳定减少多少实际计算量？
2. 5%、10%、15%、20% 中，哪个精度与效率最平衡？
3. 精度恢复来自 BN 校准、普通训练，还是教师蒸馏？
4. YOLO11s、YOLO11m 和 DINOv2 哪种教师更有效？
5. GMAC 下降是否真正带来推理加速？

Taylor 是根据现有结果选出的主方法，不是已经证明的最优方法。如果所有节点恢复都很差，再另立实验，与 L1、BN-scale 等方法做同 GMAC、同训练预算对照；本实验中途不反复换方法。

## 5. 19A：raw 剪枝阶梯

### 5.1 嵌套关系

```text
5% 删除集合 ⊂ 10% 删除集合 ⊂ 15% 删除集合 ⊂ 20% 删除集合
```

10% 从 5% raw 继续，15% 从 10% raw 继续，20% 从 15% raw 继续。到达节点时复制 checkpoint 用于后续实验，主路径仍沿 raw 权重向前。

### 5.2 每一步怎么剪

1. 在固定 calibration 集重新计算当前模型的 Taylor 通道分数。
2. 只考虑实验16确认可剪的安全层。
3. 对每个候选层模拟删除 8 个输出通道。
4. 通过依赖图同步相关层，检查结构和检测输出。
5. 计算该动作真实减少的 GMAC。
6. 计算：

   ```text
   候选代价 = 被删通道 Taylor 分数之和 / 本步实际减少的 GMAC
   ```

7. 接受候选代价最小的可行动作。
8. 保存步骤记录，在新模型上重新计算 Taylor。
9. 达到当前 GMAC 目标后保存 raw checkpoint，再继续下一档。

**实际 GMAC 降幅是硬目标；通道比例只是单层安全上限。**

### 5.3 层级上限

实验16的 low、medium、high 分层只做一次；每次剪枝动作后仍重新计算 Taylor 通道分数。

| 目标 GMAC 降幅 | low 上限 | medium 上限 | high 上限 |
|---:|---:|---:|---:|
| 5% | 12.5% | 6.25% | 0% |
| 10% | 25% | 12.5% | 6.25% |
| 15% | 37.5% | 25% | 12.5% |
| 20% | 50% | 37.5% | 25% |

上限不是必须剪满的目标。优先 low，不够再开放 medium，仍不够才开放少量 high；每次扩大范围必须记录原因。

### 5.4 剪枝阶段的边界

剪枝阶段只负责生成计算量阶梯：

- 不在中途微调或蒸馏；
- 不用 mAP 控制每一步的接受或回退；
- 不用训练后的权重继续剪；
- 不把四个独立搜索的模型称为嵌套阶梯；
- 不使用旧 `best.pt` 冒充官方模型或 raw 节点；
- 不使用 SFA。目前没有实现或验证 SFA，也不能把普通 1×1 特征投影称为 SFA。

若激进节点最终无法恢复，就选择更保守节点，而不是破坏 raw 路径。

每个节点必须能重新加载、前向、反向；输出维度正确；无 NaN/Inf；参数量和 GMAC 复测一致；保存通道结构、步骤和 SHA256。

## 6. 19B：BN 校准和 source

BN 校准只更新 `running_mean`、`running_var` 和计数器，不反向传播，不更新卷积权重或 BN affine 参数，不改变结构。

先读取 BN 扩展扫描最新 `run_info.json`，确定一套统一配方。四个节点必须使用同一配方。

| BN 项目 | 最终值 |
|---|---|
| 图像数 | 待读取正式扫描结果 |
| momentum | 待读取正式扫描结果 |
| 重置统计量 | 否 |
| 更新权重 | 否 |

每个节点保留 `raw.pt` 和 `bn_calibrated.pt`，在 tune 集选择较好的一个作为该节点 `source`。随后在 val2017 评价 source，建立训练前基线。

```text
同一节点 source
 ├─ control
 ├─ YOLO11s KD
 ├─ YOLO11m KD（仅入选节点）
 └─ DINOv2 KD（仅入选节点）
```

同一节点的全部训练必须从完全相同的 source 开始。

## 7. 四种训练方案

`source` 是基线，不属于训练方案。

| 方案 | 教师 | 目的 |
|---|---|---|
| control | 无 | 普通检测训练能恢复多少 |
| YOLO11s KD | 官方未剪枝 YOLO11s | 父模型蒸馏净收益 |
| YOLO11m KD | 官方 YOLO11m | 更强检测教师是否更有效 |
| DINOv2 KD | 冻结 DINOv2 | 通用视觉特征是否有额外收益 |

执行顺序：

1. 四个节点全部运行 control。
2. 四个节点全部运行 YOLO11s KD。
3. 根据恢复后的精度与计算量选择一个均衡节点和一个激进节点。
4. 两个入选节点补做 YOLO11m KD 和 DINOv2 KD。
5. 本实验不混合教师。

### 7.1 公平性

同一节点固定 student source、数据、epoch、有效 batch、优化器、学习率、增强、随机种子和 checkpoint 选择规则。显存导致物理 batch 不同时，用梯度累积保持有效 batch 一致。

正式比较前，只在 5% source 上确定一套稳定训练配方；确定后冻结，不给不同教师单独调参。

### 7.2 蒸馏实现

YOLO 教师冻结并保持 `eval()`。优先做空间对应的 P3/P4/P5 特征蒸馏；通道不同可用训练期 1×1 投影。检测输出蒸馏只有在索引、尺度和归一化单独验证后才能加入。

DINOv2 必须复用并审查项目已有实现，记录型号、权重 SHA256、特征层、输入处理、插值和投影方式，不能凭记忆编造接口。

教师和临时投影只用于训练。部署 checkpoint 只保留正常 YOLO 学生，结构、参数量和 GMAC 应与对应 source 一致。

| 正式训练项 | 统一值 |
|---|---|
| epoch | 待定，正式对照必须相同 |
| 有效 batch | 待定 |
| 优化器 | 待定 |
| 基础学习率 | 待定 |
| 数据增强 | 待定 |
| checkpoint 选择 | 在 source、best、last 中按 tune mAP50-95 选择 |

短跑只检查代码和稳定性，不能用不同 epoch 的结果判断教师优劣。

## 8. 模型选择

先删除“既更慢又更不准”的节点：

- **均衡节点**：GMAC 明显下降，精度损失较小；
- **激进节点**：计算量更低，仍有可接受的恢复潜力。

如果 A 比 B 更准且 GMAC 更低，B 就没有保留价值。这就是本实验需要的 Pareto 判断。

最终还要在同一 GPU、相同输入、batch、精度模式和预热条件下测真实延迟。GMAC 降低但延迟不降，不能证明部署有效。

## 11. 给 AI 的直接执行清单

1. 读取本文件和已有 `run_info.json`，核对状态、路径、SHA256、数据划分和实际结果。
2. 审查阶梯脚本，确认从实验17的 5% raw 开始，只沿 raw 权重继续。
3. 依次剪到 10%、15%、20% 实际 GMAC 目标；每次动作重算 Taylor，每个节点保存并验证。
4. 剪枝中途不微调、不蒸馏、不用 mAP 回退。
5. 读取 BN 扩展扫描正式结果，确定统一 BN 配方。
6. 四个节点统一 BN 校准，并从 raw/BN 中确定 source。
7. 先在 5% source 验证一套稳定的统一训练配方。
8. 四个节点运行相同预算的 control 和 YOLO11s KD。
9. 根据 mAP、GMAC 和延迟选择均衡、激进两个节点。
10. 两个节点运行 YOLO11m KD 和 DINOv2 KD。
11. 与相同预算 control 比较蒸馏净收益。
12. 保存 source、best、last，按 tune 选择 checkpoint，最后运行正式 val2017。
13. 输出总表和最终报告，不覆盖旧目录，不隐藏失败结果。

遇到未确定参数或接口时，先审查现有代码和日志；没有依据就标记“待确认”，不能编造。若起点、数据、结构或比较预算改变，必须停止正式对照并记录。
